# PhenFind: проверка кода

Проверен проект `/Users/andrejnekrasov/pro/my/phenfind`: собственные Python-файлы, JavaScript, шаблоны, CSS, скрипт загрузки ресурсов, зависимости и подготовленные данные. Исходники проекта не изменялись.

## Найденные ошибки

### 1. Не заполнен requirements.txt

Файл имеет размер 0 байт. Установка `pip install -r requirements.txt` в новом окружении не установит зависимости приложения. Работоспособность текущего окружения не обеспечивает воспроизводимый запуск на сервере.

Нужно перечислить зависимости приложения с проверенными версиями: FastAPI, Uvicorn, Jinja2, pandas и pyarrow. README также должен описывать создание игнорируемого `static/data/gene_phenotypes.json` перед запуском приложения.

### 2. Пустой HPO ID вызывает HTTP 500

Место: `hpo.py`, создание матрицы заболеваний и `get_gene_match_summary`.

В локальном `phenotype.hpoa` есть две строки `OMIM:111400` с пустым `hpo_id`. Фильтрация удаляет только `NOT`, поэтому в матрице присутствует пустой столбец.

Воспроизведение:

```http
POST /matches?mode=disease
Content-Type: application/json

[""]
```

Результат: HTTP 500, `KeyError: ''` при обращении к словарю названий терминов. Запрос `["", "HP:0001252"]` также падает.

Обычный интерфейс уже исключает пустой ID из подсказок, поэтому проблема проявляется через API. Исправление: не включать пустые ID в матрицу и отклонять либо удалять пустые ID во входном списке. После исправления подготовки матрицу необходимо пересобрать.

### 3. Некорректные HTML-атрибуты

- `templates/base.html:19`: два атрибута `class` у `body`. Браузер не объединяет их автоматически; нужно записать классы в один атрибут.
- `templates/gene.html:12`: лишняя двойная кавычка после значения `style`. В разобранном HTML появляется отдельный некорректный атрибут `"`.

Обе ошибки подтверждены разбором отрендеренных страниц. Сейчас страницы возвращают HTTP 200, но разметку нужно исправить.

## Производительность и небольшие замечания

- `static/js/search.js:91`: `maxResults: Infinity` сохраняется. Короткий запрос может создать более 12 тысяч элементов выпадающего списка. Это риск задержек отрисовки; ранее измеренная фильтрация самого массива занимала около 3–4 мс. Проблемы отрисовки здесь не измерялись в браузере.
- `get_gene_match_summary` на каждом запросе заново создаёт словарь названий и обходит строки через `iterrows()`. В предыдущих замерах этот этап занимал больше времени, чем поиск по матрице. Это возможность оптимизации, а не ошибка результатов.
- `utils.py:7`: функция аннотирована как возвращающая `str`, фактически возвращает `Path`. Текущему выполнению это не мешает.
- `static/js/search.js`: `const mode` объявлен до `try` и повторно внутри `try`. Области видимости разные, поэтому синтаксической ошибки нет, но одно объявление лишнее.
- `prepare_data.py` использует `Path.cwd()`. Его следует запускать из корня проекта; при запуске из другой папки пути будут другими. В README это стоит явно указать или заменить основу путей на расположение скрипта.

## Что проверено успешно

- Синтаксис всех четырёх Python-файлов, обоих JavaScript-файлов и `download_vendor.sh`.
- 22 обычных сценария API и шаблонов: оба режима, порог совпадений, пустой выбор, неизвестные ID, повторы терминов, неверные параметры, страницы известных/неизвестных генов, регистр символа гена и подсветка.
- Порог применяется к уникальным выбранным ID; повтор ID не увеличивает число совпадений.
- В общем списке генов нет повторов и значения `—`.
- Столбец Disease присутствует только в режиме заболеваний.
- Подсветка добавляется при передаче `highlight`; обычный переход на ген её не сохраняет.
- Подключённые из HTML локальные CSS, JS и изображения существуют.
- Защита от устаревших ответов в JS: более ранний ответ не заменяет новый результат, очищенные результаты или результаты другого режима. Проверено с имитацией запросов.
- Обработаны нулевые результаты, очистка и смена режима в проверенной логике JS.
- Количество уникальных связей в каждой строке обеих матриц совпадает с исходными файлами.
- Все гены из матрицы имеют запись в словаре страниц генов.
- В подсказках отсутствуют пустой ID, All и Mode of inheritance.
- В текущем phenotype.hpoa не найдено пар «заболевание — термин» одновременно с положительной аннотацией и NOT.
- Загрузчик проверен на локальном файле: загрузка, пропуск уже существующего файла и удаление временной папки работают.

## Границы проверки

API проверялся непосредственно через ASGI без запуска нового сетевого сервера. JavaScript проверялся синтаксически и с имитацией части DOM/запросов. Полного визуального прогона в реальном браузере, нагрузочного тестирования и проверки работы на удалённом сервере не было. Подготовленные пользовательские данные не перезаписывались; скачивание из интернета не запускалось.
